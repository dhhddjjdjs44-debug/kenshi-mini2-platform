# 8. Прошивка и восстановление: полный безопасный процесс

**Это описание процесса, НЕ разрешение и НЕ команда начать.** Папка TheLastV
не содержит writer/DA/NOR images. Все старые физические attempts SPENT.
Ни прежнее «разрешаю всё», ни наличие файлов, ни USB-storage «Да» не заменяют
свежую аппаратную готовность и проверенный план конкретной новой операции.

## Источники правил перед каждым действием

Открыть актуальные, не только архивные копии:
- `C:/Users/USER/Documents/Codex/2026-11-16/senior-embedded-c99-developer-reverse-engineer/AGENTS.md`;
- там же `PHONE_OPERATION_RU.md`;
- `C:/Users/USER/Documents/Codex/2026-11-18/new-chat/work/current_installed_firmware.json`;
- current pointers, отчёт/manifest именно выбранного кандидата.

Копии в `originals/` для контекста и аудита. Там есть исторические разрешения,
ошибочные/исправленные карты, старые хеши и старые transport варианты. Их не запускать.

## Неприкосновенные границы

NOR4MiB `[0x000000,0x400000)`. Допустимое ОКНО очередного bounded writer:
**`[0xB000,0xF000)` — ровно 0x4000 байт, четыре 4096B сектора 11..14**.
Весь NOR вне этого окна должен остаться побайтно равным свежему before.
Это включает NV/IMEI/конфигурацию, а не только известные boot сектора.

Нельзя full erase/full restore/format, стирать все 4MiB или переписывать original
full dump ради восстановления. Нет операций с диском ноутбука и таблицами разделов.
Только неизменённый оригинальный IoT DA, без обхода защиты/модифицированных DA.
Текущая политика новых проб: original cold BootROM→DA, БЕЗ UseExistingDA/fallback.

## Подготовка кандидата офлайн

1. Определить цель: конкретный sdk/doom candidate либо bounded stock-code restore.
2. Не менять sealed V11/V12/0.1/frozenHW02. Продолжать допустимую UNSEALED копию
   или создавать новую с provenance; не смешивать чужие бинарники.
3. Проверить исходники/сборку/model tests/linker map/RAM/stack budget/размер загрузчика.
4. Зафиксировать pins/hash загрузчика и PLAT.ELF, разрешённый card allowlist.
5. Для restore извлекать только допустимые code bytes оригинала, сохраняя live outer/NV.
   Архив original полного дампа — источник code/reference, не live baseline.
6. Собрать expected overlay из **reviewed** before + разрешённой замены.
   Ни один неразрешённый байт не менять; проверить exact range/размер.
7. Новый отдельный one-use attempt/session, reviewer checks и bounded launch.
   Старый runner не переиспользовать и не редактировать ему base «чтобы совпало».

## Готовность и fresh baseline

1. Пользователь у телефона, текущее питание/кабель/карта и цель операции известны.
2. Единственный USB владелец, нет других flash/dump/MTK программ.
3. Новое холодное ручное подключение по [режимам](02_PHONE_MODES_RU.md).
4. Стандартный BootROM handshake и original DA, проверить действительную фазу протокола.
5. В **этой же живой DA сессии** прочитать геометрию и полный fresh before 4 MiB.
6. Сверить все параметры и SHA256 с закреплённой reviewed base кандидата ДО D3/D5.
7. Несовпадение, ошибка или неоднозначность → STOP до erase.

Если stock изменил NV, старый base закономерно может не подойти. Это НЕ повод
принять любое новое чтение автоматически. Нужны отдельный read-only capture,
независимый review расхождений, новый кандидат/pins и новая физическая готовность.
После standalone read-only capture не предполагать, что DA остался пригоден для записи.
Нельзя auto-repin/автооткат, скрытое принятие unexpected bytes или «ignore checksum».

## Сама ограниченная запись

Только когда все gates совпали: D3/D5 в четырёх разрешённых секторах.
Зафиксированный рабочий transport: packet_length=4096, marker отдельно,
данные 64 отдельными USB OUT по 64B, BE16 checksum отдельно, затем ACK69;
erase timeout bounded60s. Не склеивать это в один 4099-байтный transfer.
Не добавлять F0, CDCSET_LINE_CODING/SET_CONTROL_LINE_STATE или неизвестные
control transfers. Это протокольная справка, не готовый пригодный сегодня writer.

Любой STALL/timeout/short transfer/unexpected ACK → немедленный STOP. Никаких
автоматических retry/reset/FINISH/reconnect/clear-halt/reuseDA/fallback/rollback.
Сохранить session/logs и точно отметить, дошло ли выполнение до D3/D5.

## Обязательная проверка ПОСЛЕ, ДО перезапуска

1. Полный full after 4 MiB, не только прочитанный обратно loader.
2. Точное побайтное совпадение с expected overlay.
3. Полный SHA256; проверить все изменившиеся 4096B блоки — только 11..14.
4. Все байты outer/NV вне окна равны same-session fresh before.
5. Проверить код/loader pins/PT_LOAD выбранной пары, если установлен custom.
6. Независимый аудит и сохранение before/after/manifest/session metadata.
7. Только PASS позволяет записать verified installed pointer.
   «Успел отправить данные» и expected SHA не являются readback.
8. Не слать автоматический reset/FINISH. Ручной старт только после
   `verified_without_reset`, по согласованной процедуре питания.

Installed pointer — итог подтверждённой записи; не менять его на candidate только
из-за успешной сборки. После stock boot свежая база снова требует нового чтения.

## Как возвращать stock

Не копировать весь factory dump во flash. Новый one-use bounded restore заменяет
только код внутри `[0xB000,0xF000)`, сохраняет свежие внешние/NV байты и проходит
ту же full before / full after / outer audit. Если различия кода вне окна обнаружены,
этот bounded план их НЕ исправляет: остановиться и разработать отдельный план,
не расширять запись молча. IMEI/NV восстанавливать из чужого дампа нельзя.

## Если проверка провалилась

Не перезапускать тот же writer. Сначала зафиксировать фазу, результаты, last PC/
error code и сохранить каталоги. Не считать телефон установленным/восстановленным,
пока нет независимого полного аудита. Не обещать гарантированное восстановление
из одного факта, что original dump есть. После отказа — отдельное расследование
и новая осознанная физическая проба, не автоматическое «ещё раз».
