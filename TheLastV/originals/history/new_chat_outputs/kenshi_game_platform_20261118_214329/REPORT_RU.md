## Частота: что удалось установить без гаданий

B621 — не доказательство ошибочного медленного режима. Оригинальная функция BL1
Thumb `0x10001D70` сама записывает B621 по `0xA0010108` из `0x10001E0E`.
Точное исполнение исходных байтов для профилей 2/3/5 в модели подтвердило это;
для 2/5 итог MPLL=1401, DIV=0, для 3 — MPLL=1801, DIV=0.
Это не расшифровка bit0 и не измерение фактической частоты ядра.

Ранее на телефоне DRAW≈174 мс, DMA≈21,7 мс, около5 FPS диагностического экрана.
DRAW включает ожидания NOR/PSRAM. Пользователь сообщил совпадение SEC с внешними
60 секундами, но точность не зафиксирована. Новая TCM-петля исключает из тела
замера framebuffer и чтение кода из NOR; PLL/делители/EMI/кэш не перенастраиваются.

## Doom: что именно входит и что мешает игре на телефоне

PureDOOM, upstream commit `355cfbd16fac119718879239336ee2ea408886bd`;
исходный vendor header и GPLv2 license сохранены побайтно. Свой backend:
аллокатор с объединением блоков, read-only потоковый WAD, события клавиш с
агрегацией алиасов, часы, палитра и вывод320x200 ->128x80 по центру128x160.

RAM ELF SHA-256: `27d0ee1cc7138c277533037f531278c81ec7473ee50da9272e2c85bc5c791da3`.
Связанная обычная RAM-разметка помещается в проверенные4 МиБ; аллокатор3 МиБ,
после E1M1 занято 2767768 байт в нём. Все PT_LOAD и предел4МиБ
проверены. Пересборка из поставляемых исходников дала те же загружаемые PT_LOAD.
ELF — **не самостоятельный boot image, не прошивка MAUI и не 16-КиБ patch**.
Нужны доказанные загрузчик/RAM-layout, инициализированные RAM/LCD и источник WAD.

Проверочный WAD: 4196020 байт, аппаратная RAM:4194304 байта.
WAD сам больше RAM на1716 байт, ещё до движка: нужен потоковый доступ к карте
или иному проверенному хранилищу. Сам engine text+data≈315КиБ также не влезает
в разрешённый16-КиБ flash patch. Диапазон NOR для обхода проблемы не расширялся.
**WAD, полный NOR и DA не включены.** Физический аудиотракт не подменён
программным микшером; неизвестные AFE/PMIC адреса не трогались.

Управление backend:2 вперёд; LEFT/RIGHT поворот; DOWN или8 назад; OK выстрел+
Enter, зелёная выстрел;5 use; левая soft Escape;4/6 strafe;* run;0 automap.
UP/RIGHT bit30 пока не разделены по исходным фото, поэтому вперёд — числовая2.

## Пройденные проверки

- C99 strict build и11 packaging-тестов.
-26 native diagnostic и10 clock-native случаев на точном итоговом V3 ELF.
-11 TCM/VIBR native случаев, включая остановленный GPT, отказ включения,
  reserved VOSEL, уже активную линию и восстановление исходного слова.
-4 одинаковых растровых workload,260 текстовых случаев и8 границ bars:
  точное совпадение пикселей/клиппинга; отдельный подсчёт ARM-инструкций.
- Heap: +1МиБ BSS проходит; +2МиБ отвергается требуемым ASSERT.
- Оригинальный BL2/GFH и отрицательные контроли; независимый overlay/ELF audit.
- Doom:64 ARM-кадра E1M1,6 проверок агрегации ввода,4 blit/NULL/DMA-защиты,
  software PCM ненулевой; нет MMIO writes в Doom fixture.
- Исходные sealed V2 и writer manifests проверены, файлы не изменены.

**Эмуляторные тайминги, искусственный WAD callback и LCD completion boundary
не являются аппаратными измерениями.** Единственный следующий физический шаг —
одна применимая авторизация записи именно V3 и новая ручная готовность телефона.
Текущий spent writer не запускался/не перенастраивался; прежние разрешения не
переиспользованы. Для записи сохраняются штатные same-session geometry,
fresh4MiB-before, точные hash pins, полный4MiB-after и независимый outer-byte audit;
без retry/reset/FINISH/reconnect/rollback.
