# Kenshi: диагностическая DOOM TRACE V6 готова, НЕ ЗАПИСАНА

2026-11-19T13:52:12.442269+05:00

## Аппаратное наблюдение
V5 загрузила ELF и вошла в RAM-движок; D007 подтверждает возврат нужного количества
байт из первого WAD read. Пользователь сообщил: «Да, держит на этом».
Первого игрового кадра нет; точная длительность непрерывного ожидания не измерена.
Причина остановки пока НЕ установлена. Новых USB/flash/SD-операций не выполнялось.

## Что изменено
V5 показывала только первое WAD read. Последующие ошибки чтения, print-log и
невыходящий fatal движка оставались невидимыми. V6 добавляет:
- DOOM INIT V6: RD — число последующих WAD callbacks, OFF — последний offset;
  последние48символов содержательного сообщения движка, в верхнем регистре.
- WAD IO ERROR V6: последующая ошибка/короткое чтение; PH/ERR/LBA сохранённого
  алгоритмом секторного снимка. UI не перечитывает read-to-clear SD-флаги.
- DOOM FATAL V6: код exit и последнее сообщение; затем вызывается исходный fatal.
- TRACE NOT BOUND: ожидаемые указатели callbacks не совпали, подмена НЕ выполняется.

Перехватываются только RAM DATA указатели штатных print/exit callbacks, и только
когда оба равны ожидаемым исходным функциям неизменённого DOOM.ELF. Инструкции
движка НЕ патчатся. Обработчики устанавливаются на первом ПОСЛЕДУЮЩЕМ WAD callback:
фатал/задержка ДО этого момента всё ещё вне перехвата. Это явное ограничение.
После первого игрового кадра PIO-лог подавляется; на следующем callback возвращаются
исходные указатели. PIO только при idle LCD, полный экранный window восстанавливается;
старый NOR framebuffer и его DMA после handoff не используются.

Файлы DOOM.ELF/DOOM1.WAD на карте менять НЕ требуется. SDdividerF0, CPU/PLL,
напряжения, pinmux, EMI и алгоритмы контроллера/инициализации прежние. Для размера
только NOR-копии LCD/clock/MSDC дополнительно собраны Thumb. Карточный RAM-движок
включая его драйверы побайтно прежний.

## Следующий физический шаг
Выключить телефон, отключить USB, вынуть аккумулятор и подключить USB для записи.
Готовность подключения — необходимое физическое действие, не повторный вопрос
о разрешении работать. Старую V5 попытку НЕ перезапускать. Для V6 нужен отдельный
candidate-bound writer, та же защита четырёх секторов, fresh full same-session
before gate ДО D3/D5 и full after+independent audit; никаких автоповторов,
reset/FINISH/reconnect/clear-halt/rollback. Сейчас на телефоне всё ещё V5.
Hardware audio не реализован; физического игрового кадра пока нет.
