# Kenshi Mini 2 — CLK DIAG V2: готово офлайн, НЕ записано

## Задача

По просьбе «Давай делай» подготовлена отдельная сборка для проверки гипотезы
CPU 26 против 260 МГц. Телефон, USB, NOR, драйвер и питание не трогались.
Сейчас установлен прежний CORE DIAG V1 с подтверждённым полным NOR
`0ae74dc92ad51a33e48f2e78ba54c57b5c651f38f300027306d8f390a36dc1ec`.

## Новый экран

- `REG BOOT NOW`: две колонки сырых значений. BOOT — сохранённые снимки
  загрузки, NOW — новые read-only 16-битные чтения перед подготовкой кадра.
- `MCU`: 0xA0010108; `MPLL`: 0xA0170100; `DIV`: 0xA0170104.
  Никаких записей в эти регистры и изменений PLL/делителей не добавлено.
- `DRAW US`: длительность построения предыдущего полного кадра CPU.
- `DMAX US`: максимальная такая длительность за этот запуск.
- `DMA US`: длительность предыдущей передачи, измеренная существующим
  polling-драйвером, от его стартовой отметки до обнаружения завершения.
- `XMAX US`: максимум этой длительности передачи.
- Оставлены SEC, FRAMES, FPS, P/R, пять RAW KEYS, RAM 4096K OK и HEAP GUARDS OK.
  Двигающаяся тестовая полоска занимает нижние 16 строк экрана.
- `GPT26M` и любая классификация CPU MHz с основного экрана убраны.

У DRAW есть **задержка на один завершённый кадр**: измерить ещё не законченный
кадр внутри его же картинки нельзя. Первый DRAW=0 до первого завершённого
замера. Max сравнивается по сырым uint32 GPT ticks; вычитание поддерживает
один переход счётчика через ноль. Девять цифр US не теряют верхний разряд
максимального uint32 GPT delta / 26.

Все значения US используют прежнее предположение GPT=26 МГц. Это **не CPU
cycle counter и не независимое измерение частоты ядра/осциллятора**. Точность
GPT нужно отдельно сверить с внешним секундомером. DMA содержит задержку
обнаружения завершения опросом и не является чистым аппаратным bus-time.
Суммировать DRAW и DMA как гарантированную полную длительность кадра нельзя:
вне этих границ остаются опросы/прочие операции. Новые надписи и большая
область UI меняют нагрузку относительно V1 — это инструментирование,
а не оптимизированный speed benchmark.

## Изменения и безопасность

Из production-файлов изменён **только src/main.c в новой копии проекта**.
Boot/RAM-тест, GPIO, LCD init/transfer protocol, clocks, cache, PLL, SFI, EMI,
PMIC, напряжения и power-hold остались побайтно прежними. Дополнительный файл
тестов — tests/verify_clock_diag_native.py. Исходный установленный candidate
и writer сохранены, их манифесты проверены неизменными.

Аудио, вибро и microSD не реализованы. `SD AUDIO NO TEST` ожидаемо; новая
сборка не даёт результатов тестов этой периферии.

## Проверки

- C99 ARMv5TE build с -Wall/-Wextra/-Werror и 11 packaging tests — PASS.
- 26 прежних native/model случаев на новом ELF — PASS: полный RAM boot,
  64 DMA кадра, ввод, охранные слова, ошибки RAM/alias/cache/GPT/DMA и панели.
- 10 новых native случаев — PASS: BOOT/NOW различимы, только чтение трёх
  clock-регистров, номинальные US, wrap/нулевой delta/max, предел девяти цифр,
  все строки в 128x160 и нет выхода за framebuffer.
- Heap: +1 МиБ BSS собирается, +2 МиБ отвергается требуемым ASSERT — PASS.
- Исходный BL2/GFH/entry и отрицательные GFH-контроли — PASS офлайн.
- ELF PT_LOAD побайтно совпал с логическим overlay; защищённые диапазоны
  `[0,0xB000)` и `[0xF000,0x400000)` неизменны относительно проверенного NOR.

Это синтетические проверки, **не аппаратное подтверждение новой сборки**.
Картинка clock-screen-model.png имеет пометку MODEL ONLY; её FPS/тайминги —
входы модели, не скорость и не частота телефона.

## Следующая физическая проба — ещё не разрешена/не начата

Нужны явное подтверждение записи именно CLK DIAG V2 и готовность телефона
после ручного отключения USB, снятия батареи и подключения USB без кнопок.
Нельзя запускать текущий spent writer: он намеренно закреплён на старой базе.
Необходимо отдельно подготовить штатный existing runner под точные новые
хеши, не меняя протокол/диапазон, затем выполнить все исходные same-session
проверки геометрии, свежего полного before, полного after и защищённых областей.
Никаких автоповторов, reset/FINISH/reconnect/clear-halt, откатов или repin после
неудачи. В эту офлайн-работу ни одна из этих операций не входила.

После успешной будущей записи: обычный холодный старт, фото регистров и
DRAW/DMA/FPS после 30–60 секунд работы. Из сырых данных ещё потребуется
разобрать выбор источника/делителей; одно число FPS не доказывает CPU MHz.

## Исходники

Полный source-only проект вложен в project/. rtc_model.py лежит рядом с ним
для native fixtures. Build требует ARM GNU toolchain, pyelftools/Unicorn для
модельных тестов и исходный NOR через явный --dump. Полный NOR и stock DA
в комплект не включены. Бинарник называется UNFLASHED намеренно.
