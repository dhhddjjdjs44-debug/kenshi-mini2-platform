# Kenshi Mini 2 — оставшиеся кнопки, фото 1–13

Дата: 18 ноября 2026. Анализ локальных файлов, без операций с телефоном.

## Как сопоставлены снимки

Пользователь прямо указал: «Вот, у них названия файла это твой порядок».
Номер в `photo_N_2026-11-18_18-15-54.jpg` соответствует ранее запрошенной
кнопке. Порядок вложений не используется. Оригиналы скопированы без изменения
в work, SHA-256 сверены; опубликованы только обрезки LCD, без фона монитора.
Маски прочитаны вручную на обрезках в разрешении оригиналов, не старым OCR.

На первой строке HUD четыре 16-битных слова MEM1–MEM4, в начале второй —
MEM5 & 0x3FFF. Это отображённые **нажатые** биты, инверсия active-low raw.
Нумерация битов с нуля: `16 * номер_слова_с_нуля + бит_в_слове`.

## Что нельзя замалчивать

1. **→ и ↑:** на обоих оригиналах `0000 4000 0000 0000 0000`, bit30.
   Это два одинаковых наблюдения, а не подтверждение двух разных контактов.
   Из этих масок программа не может различить две кнопки. Причина пока не
   установлена: снимки не доказывают постоянное электрическое объединение,
   ошибку пользователя, неисправность либо дефект сканера. Для уточнения нужны
   только раздельные нажатия → и ↑ с полным отпусканием между ними.
   Старый RIGHT30 fixture был синтетическим; новые фото впервые дают
   пользовательскую подпись RIGHT для bit30, но дубликат UP остаётся нерешённым.
2. **Красная трубка:** на фото №4 все пять слов равны нулю, как при idle.
   Бит этой кнопки не найден. Нельзя утверждать, что она сломана или вообще
   нигде не считывается. Старый видео-кандидат bit72 этим фото не подтверждён.
   Полезен короткий ролик краткого нажатия при видимом LCD, не длинное
   удержание питания. Новых USB/DA/прошивочных действий для этого не нужно.
3. **\*:** новое фото №12 показывает MEM1 0x0008 = bit3. В установленном
   `diagnostic_main` проверяется `(raw[0]&4u)==0u`, то есть bit2. Комментарий
   «hold STAR» не соответствует новой фото-маске. Применение выражения к
   этой маске даёт false; это статическая проверка, не проверка холодного
   старта телефона. Текущий вход в обучение через реальную * не подтверждён.

## Проверка точного установленного кода, без телефона

- ELF SHA-256: `a131080527ad8e65e96b0ea0fa7f8c5d29e824468333fcf4fb6231b6277eb333`.
- Его PT_LOAD побайтно совпали с сохранённым историческим full NOR readback
  SHA-256 `2d9f37c4a3507beb1dfde876f6cf88dff538f6ab7e91a444abb4e9b905bca2f3`.
  Это **не новое чтение устройства**.
- Точный ARM-код `matrix_init/matrix_poll` исполнен в Unicorn:
  idle + 78 одиночных битов = **79/79 PASS**, комбинации и reserved bits PASS.
- Все **13/13 новых фото-масок PASS**: в текущих defaults все возвращают
  `NONE`. Это объяснение текущей программы, не назначение новых действий.
  Ранее DOWN15 возвращает LEFT, LEFT21/OK42 — NONE.
- RAM learner заново не проверялся этой серией; прежний синтетический тест
  не доказывает физическую раскладку и холодный вход. Debounce/временные
  свойства железа не измерялись. Heap из ELF не является новым RAM-тестом.
- Исторические manifests проверены без изменения: 223, 98, 4, 4 записи.

## Дальнейшее действие

Повторять всю клавиатуру не нужно: уточнить →, ↑ и краткое нажатие красной
трубки. Затем можно отдельно исправлять управление и STAR shortcut в
офлайн-копии. Текущая серия **не создаёт новую прошивку и не разрешает запись**.

Исходники/ELF/прошивки, writer, NOR, загрузчики, PLL/EMI/PMIC, физические сессии
не изменены. Единственные изменения в старом проекте — новые текстовые
наблюдения в AGENTS.md и PHONE_OPERATION_RU.md; их исходные версии сохранены.
Предыдущая одноразовая flash permission израсходована; запрещено автоматически
перепривязывать writer, повторять запуск, reset/reconnect/rollback. Для будущего
разрешённого испытания диапазон по-прежнему только [0x00B000,0x00F000), со всеми
предыдущими same-session fresh-read/geometry/bytewise-before-after проверками.
