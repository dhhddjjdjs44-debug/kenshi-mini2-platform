## 2. Карта/установка — только отдельная проверенная операция

Новый loader ожидает `PLAT.ELF`, `KDATA.PAK`, optional `DOOM1.WAD`.
Старые V11/V12 loader не умеют этот контракт. Копирование одного нового ELF под
старым именем ничего не устанавливает.

- Только свежая идентификация настоящей microSD телефона: нельзя предполагать букву.
  Карта16GB сообщалась пользователем, это не текущее доказательство device identity.
- Stock → карта → кандидат допустимы как будущий согласованный процесс, не ночная команда.
  Если stock изменил NV, требуется новый полный read-only baseline и review.
- Разрешаемый card allowlist в пакете содержит **ровно** PLAT.ELF/KDATA.PAK.
  Сохранить DOOM1.WAD/старый DOOM.ELF/остальное, без форматирования, удалений,
  переименования тома и любых host-disk block операций. Нужен flush/reopen/full SHA256.
- Никакого full NOR restore. Только `[0xB000,0xF000)`, sectors11..14.
  Та же стандартная DA/protocol. Новый one-use attempt; никогда не запускать SPENT.
- Перед записью: same-session geometry и свежий полный4MiB before,
  независимое совпадение с проверенным актуальным baseline.
- После: полный4MiB readback, bytewise exact-overlay/outer/NV и PT_LOAD audit.
- Нет автоматического retry/repin/reset/FINISH/reconnect/clear-halt/rollback.
- Offline reference-overlay audit не является live authority. Физического writer
  этот пакет не создаёт/не содержит.

## 4. Калибровка кнопок

Открыть RAW KEYS. Сначала все отпущены; затем по одной physical UP/DOWN/LEFT/RIGHT,
OK, обе soft/back/call; отдельное фото каждого. Сопоставить raw changes с уже известными
numeric fallback. Не назначать одному raw bit противоположные направления наугад.
При необходимости исправление keymap — новая сборка/проверка, а не правка sealed пакета.

## 5. Следующие отдельные аппаратные milestones

1. **Мотор:** проверить board/допустимое напряжение, затем тихий ограниченный test
   с гарантированным off/restore, пользователь подтверждает ощущением. PMIC readback≠мотор.
2. **PCM:** сначала доказанный digital sink/буфер+clock/power routing, затем очень тихий
   короткий тон, фактический звук из динамика, далее mono PCM из этого SDK.
   Не писать в предположительный FIFO/AFE domain из интернет-примера.
3. **CPU:** получить доказанную mux/source/div chain/документацию или независимый
   clock measurement. B621/1401/div0 и GPT26MHz не означают измеренные260MHz CPU.
4. **С реальным sink:** music/EOF/pause, затем video sample-clock sync, затем Doom PCM;
   аппаратные DMA/cache ownership/underruns/volume проверяются заново.

Это список незакрытого, а не обещание выполнить всё за несколько минут.
