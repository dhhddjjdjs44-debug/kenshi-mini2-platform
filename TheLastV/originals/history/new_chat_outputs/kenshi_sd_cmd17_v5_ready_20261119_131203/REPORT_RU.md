# Kenshi — разбор видео V4 и диагностическая V5

2026-11-19T13:12:03.415382+05:00

## Что действительно видно
Видео длительностью13,57с. Сначала служебные метки B101…B105, затем:

```
DOOM LOAD V4
FILE ERROR
00000001
ST 09 PH 0D05
ERR 0000D210
CS 00000001
DS 00000000
```

V4 физически запустилась, идентификация SD прошла. В storage_open вернулся
FR_IO=-1, sd_board.error=D210 означает отказ msdc_read_sector. Это НЕ код
«файл не найден» (FR_NOTFOUND=-5). Загрузка ELF ещё не вызывалась, игрового кадра
нет. PH/CS/DS остались от идентификации: по ним нельзя назвать причину CMD17.
Неизвестны LBA, число принятых слов, timeout/CRC/R1/FIFO. Не доказаны ни потеря
файлов, ни повреждение карты, ни неверная частота CPU. Новых USB-операций0.
Общая длительность загрузки/ожидания за пределами ролика не измерялась.

## Что подготовлено, но ещё НЕ записано
**DOOM SD V5** сохраняет этапы V4, дополняет экран точными снимками CMD17:
PH/CS/DS/LBA/WD/STA. WD — принятые32-битные слова, полный сектор=0080(128).
STA — последний использованный алгоритмом снимок FIFO, не дополнительное чтение.
Read-to-clear статусы по-прежнему считываются один раз за итерацию, защёлкиваются
программно; UI их не читает. Повторные попытки после ошибки не добавлены.

После идентификации больше не повышаем частоту SD: делитель остаётся F0
вместо0C. Это консервативная **проверяемая гипотеза**, а не установленная причина
и не обещание исправления. Загрузка с карты может стать медленнее. CPU/PLL,
напряжения, pinmux, EMI и LCD-драйвер не менялись. Для размера NOR sd_board.c
собран Thumb; реальные переходы и подготовка RAM проверены моделью.

Файлы DOOM.ELF/WAD на карте не меняются, ничего копировать/форматировать не нужно.

## Коды PH для CMD17
-1100: сектор успешно прочитан;
-1102: небезопасная конфигурация;
-1103/1104: SD/контроллер занят до команды;
-1105: FIFO не пуст до команды;
-1106: нет завершения команды;
-1107: ошибка командного статуса;
-1108: ошибка статуса данных;
-1109: ошибка R1;
-110A: принято менее128слов;
-110B: нет признака окончания данных;
-110C: SD остаётся занята после чтения.

## Проверки
212 unit/model/packaging-групп PASS. 32 регрессии CMD17 дополнены проверкой
точного PH/защёлкнутых статусов/отсутствия повторов. Четыре новые модели полного
пути ошибки → FILE ERROR проверяют command timeout, DAT CRC, грязный и короткий
FIFO. Это искусственно заданные отказы, НЕ воспроизведение доказанной причины
ошибки именно этого телефона. Две ARM-интеграции прошли по64кадра, финальный
модельный кадр идентичен V4. На железе V5 не запускалась.

Образ16348байт, запас36байт в прежних16КиБ.
ELF/GFH/ARM-Thumb/границы памяти проверены независимо. Все152 файлов
запечатанной V4 неизменны. Аудиовыход не реализован; FPS/CPU MHz не измерены.

Image SHA-256: `0a05f25129d614d81a74853a0737d676ae7905bcc29b402f1c9d19e132bf550c`.

## Следующий шаг
На телефоне остаётся V4. Разрешение её записи израсходовано. Для одной новой
пробы V5 требуется новое явное подтверждение; только[B000,F000), same-session
fresh full4MiB equality gate до D3/D5, full after+independent audit. Без
автоповторов/reset/FINISH/reconnect/clear-halt/rollback и без расширения диапазона.
