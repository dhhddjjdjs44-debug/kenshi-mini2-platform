## 1. Домашнее меню и запуск игр

- Пункты: «Игры», «Телефонный режим», «Музыка», «Видео», «Настройки/диагностика».
- Управление крестовиной, OK и проверенной кнопкой возврата. Диагностические сочетания не мешают обычному использованию.
- В «Играх» список поддерживаемых игр по названиям; выбор запускает игру. Целевая проверка — Doom и независимый пример нашего runtime, не линкующий Doom.
- Выход возвращает в меню; можно повторно запустить игру/другой пункт без ПК и перепрошивки между запусками.
- Допускается один RAM-пакет с несколькими приложениями либо проверенный формат наших game packages. Это не поддержка любых сторонних ELF.
- Способ запуска/возврата выбрать после проверки памяти, loader ABI и engine pins. Нельзя прыгать в ELF поверх занятой памяти оболочки. При переходах корректно завершать DMA, звук, вибро, владение памятью и состояние клавиш.
- Простой launcher теперь входит в MVP; прежнее откладывание launcher целиком отменено. Универсальный менеджер приложений по-прежнему не нужен.

## 2. Телефонный демонстрационный режим («показ на охране»)

- Привычный домашний экран/часы, простое меню, ввод цифр, удаление символа и возврат.
- **Любой введённый номер после кнопки вызова открывает экран IMEI**, а не совершает звонок. Можно также поддержать обычный путь *#06#.
- Показывать исходный IMEI этого телефона только после достоверного установления из его stock-данных/интерфейса. Не генерировать случайный «реальный» идентификатор, не менять IMEI модема/NV и не публиковать его в отчётах/промптах. Если неизвестен — «IMEI недоступен».
- Настоящие звонки, SMS, регистрация в сети и модемный стек не входят в принимаемое сейчас понимание имитации. Элементы UI не считать работающей связью.
- Батарею/сигнал показывать как реальные измерения только при проверенном источнике. Декоративные элементы не считать аппаратной телеметрией.
- Режим работает независимо от Doom и имеет понятный выход. Вид уточнить при показе первой версии.

## 3. Музыкальный плеер

Цель — настоящий слышимый вывод файла с карты: список треков, play/pause/stop, следующий/предыдущий, безопасная громкость и выход в меню.
- Зависимость: рабочий общий аппаратный PCM sink. Сначала тихий ограниченный тон, затем непрерывный поток с корректным stop/underrun.
- Первый формат выбрать после проверки ресурсов и микшера. Допускается подготовленный PCM с конвертацией на ПК. MP3/AAC и любые произвольные файлы не обещать до реализации/замеров.
- Аудио и чтение не должны замораживать клавиши/экран. Игра и плеер используют общий драйвер; для MVP допустим один активный владелец.

## 4. Видео

Цель — последовательное воспроизведение подготовленного ролика с карты, не неподвижная заглушка.
- Первый формат/размер/FPS выбрать по измеренным бюджетам SD, памяти, LCD и декодирования. Разрешена предварительная конвертация на ПК в простой собственный формат.
- Сначала короткий ролик и устойчивый поток кадров, затем синхронный PCM через общий sink. Без физической проверки звуковую дорожку не объявлять готовой.
- Нужны play/pause/stop, конец файла и возврат в меню. Перемотку можно отложить.
- Ограниченный буфер, проверки размеров/границ контейнера и кадров, корректное LCD/DMA ownership; не загружать длинный ролик целиком в RAM.
- Зафиксировать достигнутую скорость и ограничения. Не обещать любые MP4/H.264, конкретное разрешение или 30/60 FPS без реализации и замеров.
- Конвертер и точная команда подготовки тестового медиа входят в передачу SDK. Наличие FFmpeg/другого инструмента сначала проверить.

## 5. Порядок реализации

1. Общий runtime/SDK и независимый пример; каркас меню/переключения приложений без новых аппаратных экспериментов.
2. Единая диагностика, проверка CPU и мотора, **реальный аппаратный PCM sink**.
3. Музыкальный плеер поверх sink; телефонный UI как отдельное приложение.
4. Видео: кадры, затем синхронизация звука. Тестовый ролик можно готовить локально до подключения телефона.
5. Интеграция: меню → игра → меню → музыка → меню → видео → телефонный режим, повторные переходы и целевой непрерывный 15-минутный прогон.

Объём вырос против исходного плана. Если звук/видео не закрыты к сроку — прямо назвать незакрытые функции. SDK для начала собственной игры можно передать раньше полной готовности оболочки. Пустые пункты меню не являются реализованными приложениями.

## 6. Безопасность и приёмка

Все ограничения NOR/USB/NV/карты из исходного плана и PHONE_OPERATION сохраняются. Этот документ не подтверждает готовность телефона и не запускает writer.
В NOR V12 всего 188 свободных байт; основную оболочку/медиа/драйверы планировать в RAM, размер и стек проверять по linker map.
Новые game/media assets сначала подготовить локально. Старый процесс обновления только ELF не расширять молча: для ассетов оформить проверяемый allowlist файлов/путей и отдельный операционный план; заново определить microSD, сохранить WAD и всё несогласованное. Диски ноутбука не трогать; форматирование не нужно.

Приёмка по строкам: SDK; запуск игр/возврат; телефонный UI/IMEI; реальный звук/музыка; ролик/аудиосинхронизация; мотор; частота CPU с основаниями; устойчивость.
Для каждой строки: not-implemented / implemented-unverified / hardware-verified / failed и доказательство. Модельный PASS, ненулевой PCM и PMIC readback не заменяют аппаратное подтверждение.
