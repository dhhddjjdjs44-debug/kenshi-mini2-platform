# Начни свою игру здесь

Это SDK для C99-игры на Kenshi Mini 2. Doom НЕ нужен для сборки своей игры.
Стартовый комплект помогает начать код сегодня, но не означает готовность всех
драйверов: физические звук/вибро custom не работают, частота CPU не измерена.
На телефоне сейчас stock; комплект ничего на него не устанавливает.

## 1. Что править

- `apps/demo_game.c` — твоя механика (`demo_init/update/render`).
- `apps/demo_game.h` — состояние игры, добавляй свои поля.
- `sdk/include/k_platform.h` — C API: ввод, время, RGB565, ресурсы, arena.
- `docs/SDK_API_RU.md` — контракт и ограничения API.
- `tools/pack_assets.py` — упаковка подготовленных ресурсов.

Это минимальный слот своей игры, не dynamic plugin ABI. Первую игру можно
писать прямо вместо демо; переименование/несколько своих игр добавим отдельной
регистрацией. Не связывай игровую логику с Doom, HAL или адресами регистров.

## 2. Быстрый цикл БЕЗ телефона

Из распакованной папки SDK:

```powershell
.\Preview-Game.ps1
```

Команда каждый раз пересобирает настоящий ARM C-код примера и SDK, затем
открывает его экран в окне ПК. Измени `demo_game.c`, закрой окно и запусти снова.
Нет hot reload. По умолчанию открывается своя игра; `-Menu` начинает с launcher.

- Стрелки или 2/4/6/8 — движение.
- Enter / Q — OK / левая софт-клавиша.
- Space / 5 — действие.
- Esc / E — правая софт-клавиша, назад в меню.
- Цифры, * и # — соответствующие телефонные кнопки, C — вызов.
- Закрытие окна заканчивает preview. Потеря фокуса отпускает все кнопки.

Это **ARM-код игры с тестовым HAL**, не эмулятор всего телефона. Виртуальное
время шага33ms, размер128×160, масштаб1..5. Скорость окна НЕ FPS телефона,
не MHz и не обещание30/60FPS. Звук/мотор намеренно unsupported; кнопки
используют общую C-карту, но этим не проверяются физические контакты телефона.
Диагностические регистры fixture синтетические, не live readback.
KDATA.PAK в preview ограничен2MiB (буфер теста), это не предел SD-потоков телефона.

Без окна, для автопроверки и скриншота:

```powershell
.\Preview-Game.ps1 -Headless
```

Скриншот: `build/platform/preview/MODEL_ONLY_game.png`.

## 3. Сборка кандидата для телефона

```powershell
.\Build-Platform.ps1 -Flavor sdk
.\Test-Platform.ps1 -Flavor sdk
```

Результат: `build/platform/sdk/PLAT.ELF` и ЕГО парный
`UNFLASHED_platform_loader.bin`. `PLAT.ELF` НЕ автономная прошивка.
Бинарники связаны pins по entry/размеру/PT_LOAD: после правки игры надо
пересобрать и проверить ОБА. Сейчас loader pins не разрешают произвольную замену
ELF только на SD; удобное обновление игр без NOR — ещё отдельная задача.
Не заменяй вручную DOOM.ELF и не запускай старые writers.
Развёртывание — отдельная проверяемая операция после свежей готовности телефона;
этот комплект не содержит writer, не форматирует диски и не трогает IMEI/NV.

## 4. Инструменты

Нужны ARM GCC `arm-none-eabi-*`, Python3.10+, pyelftools; для PC preview/tests —
Unicorn и Pillow, для окна — Tkinter (обычный Python с Tcl/Tk).
На текущем ПК они уже найдены, внешние tool binaries не включены в архив.
На другом ПК: установи их отдельно, укажи `ARM_NONE_EABI_PREFIX` (полный путь
с префиксом arm-none-eabi-) и при необходимости `KENSHI_PYDEPS`.
`-Python C:\path\python.exe` выбирает интерпретатор. Скрипты сами ничего из сети
не устанавливают. Для подготовленного видео/аудио нужен отдельно FFmpeg.

## 5. Что можно разрабатывать сейчас

Механику, управление, интерфейс, 2D-графику и чтение подготовленных ресурсов.
Звук и haptic вызывай через SDK, обрабатывай `K_UNSUPPORTED`, игра должна
продолжаться без них. Не считай сгенерированные PCM-сэмплы слышимым звуком.
Запись save-файлов/произвольное чтение My Music/MP3 decoder не реализованы.

Первый приёмочный проход на телефоне: launcher → своя игра → движение/действие →
назад → повторный запуск; затем raw-тестер кнопок и EST MHZ. Он ещё не выполнен
для текущего кандидата. Отдельная приёмка звука/вибро остаётся обязательной.
